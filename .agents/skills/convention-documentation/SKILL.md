# Документация проекта

Работать в рамках [convention-workflow](../convention-workflow/SKILL.md).

1. Перед изменением документации прочитать [актуальность, полезность и единый источник](references/writing.md). Проверить описываемое по коду, конфигурации, схемам и тестам; непроверенные гипотезы не превращать в текущие факты.
2. При изменении структуры, README, инструкций агентов или переносе файлов прочитать [контракт репозитория](references/repository-contract.md). Общие подробные правила остаются в skills; проект хранит свои команды, ограничения и контракты.
3. При работе с ADR, совместимостью, legacy и миграциями прочитать [текущее состояние и историю](references/current-state-and-history.md). Реально работающий переходный режим описывать как настоящее; будущие шаги — только в `TODO/`.
4. Заменить устаревшие утверждения у источника, сохранить полезные уникальные детали, исправить ссылки и зависимые инструменты, удалить прежние копии. Не дописывать историю изменений в действующее описание.
5. Сохранить README как краткий полезный вход, AGENTS — как сухую точку входа агента. Результаты разовой проверки и статус соответствия сообщать в отчёте задачи, PR или CI.

Пакет включает [минимальный AGENTS.md](../../../AGENTS.md) с общей директивой и локальной ссылкой. Для нового проекта дополнить его реальными сведениями по контракту репозитория; в существующем сохранить местные инструкции и объединить с общим блоком. В CLAUDE.md использовать `@AGENTS.md`; уникальные инструкции предварительно сохранить в каноническом месте. Источник и версия находятся в [README локального пакета](../../../docs/conventions/README.md).
