# Контракт репозитория и точки входа

## Необходимые артефакты

| Артефакт | Содержание | Требование |
| --- | --- | --- |
| `README.md` | Назначение, быстрый старт, основные действия, необходимые настройки и команды, ссылки на подробности | ОБЯЗАТЕЛЬНО |
| `AGENTS.md` | Короткая точка входа агента: применение workflow, локальные ссылки, команды и ограничения | ОБЯЗАТЕЛЬНО при agent-driven разработке |
| `.agents/skills/convention-*/` | Полный локальный набор канонических навыков со всеми ресурсами | ОБЯЗАТЕЛЬНО |
| `.claude/skills/convention-*/` | Локальные адаптеры с теми же именами и описаниями, ведущие к каноническим навыкам | ОБЯЗАТЕЛЬНО в поставке пакета для совместимости с Claude Code |
| `docs/conventions/README.md` | Индекс установленного пакета, происхождение, версия и инструкция обновления | ОБЯЗАТЕЛЬНО; в исходном репозитории находится внутри поставляемого `project/` |
| `docs/exceptional_execution_paths.md` | Реестр действующих одобренных исключительных путей; до аудита `NOT ASSESSED` | ОБЯЗАТЕЛЬНО в каждом сервисе |
| `docs/ARCHITECTURE.md` или краткий раздел README | Подтверждённые подсистемы, обязанности, направления зависимостей и критичные контракты | ОБЯЗАТЕЛЬНО в подходящем для масштаба объёме |
| Тесты и конфигурация проверок | Воспроизводимое подтверждение поведения и качества | ОБЯЗАТЕЛЬНО в применимом объёме |
| CI или документированный эквивалент | Исполняемые quality gates без специальных знаний предыдущего агента | РЕКОМЕНДУЕТСЯ; пробел фиксируется |
| `TODO/` | Единственное место планов и незакрытых задач внутри репозитория | ОБЯЗАТЕЛЬНО, если такие материалы есть |

Маленький сервис не обязан иметь отдельный документ на каждый пункт: README может включать краткую архитектуру, основные команды и ссылки. Не создавать пустые или вымышленные стандартные разделы. Реальные миграции, код, конфигурации и тесты остаются в местах, принятых для стека; правило TODO/ регулирует текст планов.

## AGENTS.md

Корневой файл отвечает на вопросы: куда смотреть, как проверить и чего не нарушать. Содержать:

- одну строку о назначении проекта;
- директиву применять `convention-workflow` перед работой и тематические навыки по задаче, с локальной ссылкой на workflow;
- локальную ссылку на индекс пакета и актуальную архитектуру;
- точные проверенные команды запуска, сборки, тестов либо ссылку на их действующий источник;
- только важные местные ограничения и контракты, неочевидные из кода;
- обязанность обновлять AGENTS и затронутые документы при изменении команд, архитектуры и ограничений.

Общие правила о текущем состоянии, планах, модульности, тестах, безопасности и реестре передаются через обязательный workflow и тематические навыки. Не дублировать их параграфами в AGENTS. Местное критичное ограничение допустимо, когда оно помогает избежать ошибки именно в этом проекте.

**Не помещать в AGENTS:** внешний адрес конвенции, её версию, commit hash или tag, полный текст стандарта, планы, roadmap, хронику, завершённые задачи, старые решения, автоматическое описание каждого файла, результаты разовых проверок и декларацию соответствия сервиса. Происхождение и версия имеют одно место — README локального пакета.

Вложенные инструкции узкие, относятся только к своей области и не противоречат корневым. При интеграции сохранять действующие команды и уникальные ограничения; не перезаписывать существующий AGENTS шаблоном.

Для Claude Code использовать корневой `CLAUDE.md` с импортом `@AGENTS.md`. При существующем CLAUDE сначала перенести уникальные нужные сведения в AGENTS или соответствующую локальную инструкцию; избегать двух канонических копий. Другие приложения подключать только через поддерживаемые ими механизмы, не обещая общей автоматической discovery.

Поставляемый [минимальный AGENTS.md](../../../../AGENTS.md) содержит только общую директиву и локальную ссылку. Он служит основой нового файла или блоком для интеграции, а не заменой уникальных инструкций существующего проекта. При подключении дополнить точку входа подтверждёнными сведениями из списка выше; при обновлении пакета не заменять её исходным минимальным файлом.

## Размещение подробной документации

Развёрнутые документы о действующем проекте **обязательно** размещать внутри корневого `docs/`: архитектура, протоколы/API, руководства, проверка и эксплуатация, справочники сторонних компонентов. У самостоятельных сервисов монорепозитория — относительно корня сервиса. Предпочтительное имя архитектурного файла — `docs/ARCHITECTURE.md`; остальные имена и подпапки рекомендуемые, а не обязательные.

В корне остаются README как вход пользователя, AGENTS и совместимые точки входа агентов, лицензии, обязательные notices и файлы, чьё размещение действительно требуется инструментом или поставкой. Вложенные агентные инструкции и skills находятся в нативных каталогах инструмента, включая `.agents/skills/` и `.claude/skills/`. Это служебные артефакты, а не основание размещать подробные документы проекта вне `docs/`.

Манифесты, конфигурации, скрипты, тестовые данные и схемы остаются в необходимых для них местах. Одна ссылка из собственного скрипта не является внешним контрактом: при переносе исправить скрипт. Все планы по [правилам TODO/](../../convention-workflow/references/planning.md) — только в `TODO/`.

В README сохранять назначение, быстрый старт, основные действия и ссылки. Длинные настройки, сценарии, полные контракты и специальные проверки переносить в тематические документы, сохраняя полезные сведения. Универсального лимита строк нет; отдельный файл ради формы не нужен.

**При переносе обязательно** обновить ссылки и навигацию, зависимые проверки, CI, скрипты и сборку. Markdown-ссылки считать относительно содержащего файла; для команд указывать каталог запуска. После проверки удалить прежнюю копию, не оставляя корневую заглушку. Если перенос нарушает обязательный внешний контракт и выходит за полномочия, зафиксировать конкретный блокер в TODO/, а не считать старое размещение соответствующим.

## Дополнительные документы по необходимости

Полезные места внутри `docs/`: `index.md`, `usage.md`, `protocol.md`, `modules/`, `workflows/`, `architecture/decisions/`, `testing.md`, `runbooks/`. Создавать лишь для реально нужного текущего содержания. Индекс включает действующие документы, а не планы и историю. Архивы и release notes, если требуются, не входят в обычный контекст текущей архитектуры.
